# WHY

totalrecall makes every Claude Code session the person turns it on in share one chat that never ends, as Victor Taelin's UniiChat design (gist 91837951a5ce5b38f341ec1ba1df6449) describes it: every message is logged forever, a cheap model folds the log into a binary tree of 512-byte summary lines, and each turn reads a 64-128 KB view of those lines instead of the old turns. The design is the spec, so a change that departs from it needs the Architect's approval.

# Facts

- `node_modules/@cmodjs/core/docs/` holds the docs of the installed `@cmodjs/core`. They match this version, and training data does not. Read the doc for the part you change, starting at `index.md`, before Claude Mod Manager (cmod) work.
- `tsc` reads `.claude-plugin/types/`, which Claude Code writes when it loads the mod. `cmod check` writes it when it is missing or links into a folder that is gone, such as after `cmod try`, so run `cmod check` before `tsc` in a fresh clone.
- `src/mod.tsx` holds the mod's `defineMod`: `/recall`, the `zoom` and `date` tools, the call to oneclaude's `addFilter` at setup and before every prompt, and the compaction of Claude Code's own copy of a recall session. `hooks/register.ts` only registers it with Claude Code.
- `cli/` is the `totalrecall` program, built with `bun build --compile`. `cli/src/filter.ts` answers oneclaude's filter phases (`~/Developer/oneclaude/docs/filters.md`): it logs each session's new history and rewrites each main turn into the system prompt and the person's instructions, then the view, then the `device:` line, then the turn, and each subagent's request into the subagent prompt, the view, and its task. `cli/src/chat.ts` holds the messages, the tree, and both views, `cli/src/log.ts` the day files and their index, `cli/src/view.ts` the merge order, `cli/src/compactor.ts` the Haiku compactions, `cli/src/import.ts` the import, `cli/src/clip.ts` where a long text's pages end, `cli/src/service.ts` the pool address and the OS service.
- The design follows UniiChat's own code, cloned at `~/Developer/references/uniichat`, wherever Claude Code allows: `Memory.ts` (the tree, the views, the compactor's order), `Import.ts`, `Tools.ts` (the subagent prompt), and `prompt.txt`.
- `totalrecall import [since <day>] [tools] [<export>…] [go]` runs on any machine. It reads that machine's Claude Code and Codex session folders and any Claude.ai or ChatGPT export given, asks the pool host's program for what it imported before (`/imported`), and posts what is new, oldest session first, to `/import`. Imported messages carry `imported: true`, show to models as `ai` when they are Claude's or a tool call, and are summarized on their own side of the tree, which turns never wait on. A turn's view leaves out an imported line until it is summarized, and leaves out the whole import while the view is over 128 KB, as it is while a large import's summaries catch up. A session the import brought in logs only what follows when recall turns on in it.
- One program serves every machine's sessions, on the pool's machine. The install step `totalrecall service install` installs `totalrecall serve` as a systemd user service or a LaunchAgent only where the pool's host is this machine. The pool address is the environment's `ANTHROPIC_BASE_URL`, then the one in `~/.claude/settings.json`, then `http://127.0.0.1:8317`.
- The program listens on port 8320: `127.0.0.1` answers the filter and the tools, and the pool host's own address answers only `/zoom`, `/date`, `/view`, `/imported`, and `/import`, for sessions and imports on other machines. A session's filter URL carries its mode and device: `/on?device=<hostname>:<folder>` or `/strip`.
- The program keeps the chat in the mod's data folder: `main/` and `tree/` hold one JSONL file per day, and `main.index` and `tree.index` 16 bytes per slot (offset, length, day, and the imported flag or the line's bytes), a message's slot its id and a line's `(2i+1)·2^l − 1`. At start the program indexes what the day files hold past the index and skips a line a crash cut short. `view.json` and `compaction-view.json` hold the views, saved at each message, `imported.json` the date of each imported session's last message, `sessions/` the keys of each history already logged, and `agents/` each subagent's own log under its id, with `names.json` mapping each id to its name.
- The compactor builds up to 64 lines at once on each side, the chat's and the import's, in message order, a merge first on a tie. It sends no tools, runs at high effort, and tries a failed call again with the pool's `retry-after` or a doubling wait up to a minute, for as long as it takes. A line whose source fits in 512 bytes is its source, with no call. A 400 or 413 from the pool, or a reply with no line or one that stopped before its end, makes the line its source cut to 512 bytes. A compaction reads the newest 32 KB of the compaction view.
- Claude Code sends the person's instructions (CLAUDE.md, the startup notes) as the first user message and a system message after it. The rewrite keeps them before the view, so each session's turns read them from the cache. Earlier turns drop out of the request, except the tools they added, which the rewrite carries forward.
- A `<command-name>` block in a user message records a local command the person ran, such as `/recall` or `/reload-plugins`, and is never a prompt to Claude, so the chat never logs it as the person's words.
- Claude Code sends words the person types while Claude works as a text block after the tool results, between "The user sent a new message while you were working:" and a paragraph starting "This is how Claude Code surfaces messages", and the chat logs only the words between them.
- An Agent tool result names the subagent's id after `agentId:`, and the subagent's own requests carry it in `x-claude-code-agent-id`. The chat names the subagent by the Agent call's `description`, numbered when another subagent already has that name. A background subagent's Agent tool result only says "Async agent launched successfully". Its report arrives later as a `system` message: a `<system-reminder>` holding `<task-notification>`, with its `<task-id>`, which is the agent's id, and its `<result>`. After a reply that ended Claude's turn it starts a new turn, and between tool calls it joins the running one. A notification with no `<result>`, such as a background command finishing, is that tool's output.
- Claude Code names the mod's tools `mcp__totalrecall__zoom` and `mcp__totalrecall__date`, and the prompt, the log, and the rewrite use those names, so a reply the filter misses still runs.
- With recall on, Claude Code counts its context from the rewritten request's usage, so it never compacts on its own. The mod runs `/compact` once the session's own messages pass 80% of its window. Its `beforeContextEnd` answers every compaction of a recall session with the program's `/view` as `{ summary }`, so no model runs and the next context starts from the chat's view, and refuses while the program doesn't answer. A compaction request that still reaches the filter, when a hook failed, starts "Your task is to create a detailed summary of the conversation so far" in its last user message; the filter logs its history and passes it unchanged. The summary that opens the next context starts "This session is being continued from a previous conversation" and is never logged as the person's words.
- A turn whose session's history was logged at its start, such as the first after `/recall` in a long session, passes through unchanged until that history is summarized.
- `cmod try . --home ~ --yes` runs one throwaway Claude Code session with this checkout, against the live oneclaude, and removes the mod when the session ends. `cmod link` would load the checkout into every running session.
- `cmod check` checks the mod and names the fix for each failure. `cmod publish --dry-run` builds the release in a temporary folder without pushing, and leaves this checkout as it was.
